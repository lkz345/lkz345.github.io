CASE2 - 智能研报生成

项目概述

这个项目是一个 AI 智能研报生成系统，核心目标是用 AI Agent 自动化券商研报的撰写流程。

技术上基于 DeepAgents 框架（LangChain 生态的 Agent 封装）+ @tool 函数注册构建，采用 ReAct 推理循环：LLM 看到工具 Schema → 生成 tool_calls → 框架路由执行 → 结果回传 → 继续推理或输出最终回答。整个工具注册和 function calling 协议层完全由框架封装，开发者只需关注业务逻辑。

系统具备六大工具能力，通过 @tool 装饰器定义：

工具 功能 底层脚本
web_search 双引擎联网搜索（DashScope + Tavily） search_market.py
query_pdf RAG 知识库检索（支持页码溯源） query_report.py
stock_price A 股实时 K 线数据（MiniQMT） get_kline.py
financial_analysis 财务指标趋势分析（ROE/毛利率/负债率） ratio_analysis.py
compare_reports_period 同一公司跨期纵向对比 cross_period.py
compare_reports_company 不同公司横向对比 cross_company.py

研报撰写采用国泰君安”五步法”框架：信息差 → 逻辑差 → 预期差 → 催化剂 → 结论+风险闭环。Agent 自主规划搜索策略，通过多轮迭代收集素材后按框架输出 Markdown 研报。

一、RAG 知识库构建（preprocess.py）

数据源

系统从三个目录自动扫描文档：

  1. data/reports/ — 用户上传的研报/券商报告 PDF
  2. data/financial_reports/ — 从巨潮资讯网自动下载的财报 PDF
  3. CASE1 sentiment_analysis_result/ — CASE1 舆情分析生成的 Markdown 报告

处理流水线

  1. 文件名解析：通过正则从文件名提取元数据（股票名称、报告类型、来源券商），支持多种命名格式（如 【华泰证券】xxx.pdf、财报_贵州茅台：xxx.pdf）
  2. PDF 文本提取：PyPDF2 逐页提取，同时支持多模态大模型（qwen-vl-plus）做复杂表格 OCR 解析
  3. 内容元数据补充：从 PDF 正文中提取股票代码、发布日期、报告期间等
  4. 文本切分：RecursiveCharacterTextSplitter，chunk_size=800，overlap=150，每个 chunk 携带完整元数据（doc_id、股票代码、页码、报告类型等）
  5. 统一 FAISS 向量索引：所有文档的 chunks 合并构建一个统一索引
  6. SQLite 元数据存储：文档级别的元数据存入 documents.db

Embedding 双后端

  • 本地模式（默认）：BAAI/bge-small-zh-v1.5，无需网络，适合离线环境
  • DashScope API 模式：text-embedding-v4，需 API Key，精度更高

支持增量处理：新文件放入对应目录后，再次运行 python preprocess.py 即可增量索引，已处理的文件自动跳过。

CASE1 舆情数据集成

这是一个跨项目数据联动的设计：CASE1 舆情分析系统生成的 Markdown 报告，会被 CASE2 的 preprocess.py 自动扫描、解析并纳入统一 RAG 知识库。这样 Agent 写研报时不仅能检索财报数据，还能引用最新的市场情绪分析。

二、RAG 检索机制（query_report.py）

采用了多查询 + BM25/向量混合检索的方案：

多查询扩展

先用 LLM 对用户问题生成 3 个不同角度的查询变体，每个变体分别检索后合并去重，提升召回率。

混合检索（HybridRetriever）

  • BM25 关键词检索：jieba 分词 + BM25Okapi，擅长精确匹配财务术语和数字
  • FAISS 向量语义检索：DashScope text-embedding-v4，擅长语义理解
  • 融合策略：score = α × vector_score + (1-α) × bm25_score，α 默认 0.5

页码溯源

每个 chunk 都携带所属文档和页码的元数据，回答时能标注”数据来源：贵州茅台2025年年报，第42页”，增强可信度。支持按股票代码过滤检索范围。

三、研报撰写：五步法 + Agent 自主驱动

核心理念

研报不是调用脚本生成的，而是 Agent 自主驱动迭代式研究。Agent 先规划分析框架，然后通过多轮搜索收集素材，每轮搜索后分析结果并发现新线索追加搜索，最后按五步法框架输出。

五步法框架

步骤 名称 核心问题
Step 1 信息差 市场还不知道/忽视了什么关键数据？（财报附注隐藏数据、现金流与利润背离）
Step 2 逻辑差 市场看到数据但推理错在哪里？（识别线性思维误区）
Step 3 预期差 一致预期 vs 实际偏离多大？量化偏离幅度
Step 4 催化剂 什么事件会触发价值重估？短期/中期催化剂时间轴
Step 5 结论+风险闭环 投资评级 + “哪个假设失效会导致结论崩塌”（国泰君安特别强调）

五种研报场景

Agent 根据用户提问自动识别场景类型：

  1. 个股深度：web_search 公司基本面 → 行业格局 → 竞品对比 → 券商评级 → 近期事件
  2. 季报速评：query_pdf 本地 RAG 优先 → web_search 市场预期对比
  3. 行业比较：web_search 各公司业绩 → 估值对比 → compare_reports_company
  4. 事件驱动：web_search 政策/新闻为主 → 受益公司 → 预期差分析
  5. 财务异常：financial_analysis 定量检测 → query_pdf 附注深挖

双引擎联网搜索

web_search 工具支持三种引擎模式：

  • dashscope（默认）：国内中文新闻、A股行情
  • tavily：国际新闻、全球宏观
  • dual：双引擎同时搜索，适合深度研报

四、Function Calling 架构

工具注册机制

6 个业务工具通过 LangChain 的 @tool 装饰器定义，框架自动从函数签名提取参数名、类型、默认值生成 JSON Schema，从 docstring 提取工具描述。DeepAgents 框架的 create_deep_agent() 内部通过 model.bind_tools() 将所有工具 Schema 绑定到 LLM。

运行时 ReAct 循环

  1. LLM 请求时携带所有工具的 JSON Schema
  2. LLM 返回 tool_calls JSON（包含函数名和参数）
  3. LangGraph 的 ToolNode 解析并执行对应工具
  4. 工具执行结果作为 role:”tool” 消息回传 LLM
  5. LLM 看到结果后继续推理或输出最终回答

除了用户定义的 6 个工具，中间件还注入了文件操作工具（read_file、write_file 等），Agent 总共有十多个可用工具。

五、技术亮点总结

亮点 说明
五步法研报框架 国泰君安方法论结构化输出，风险闭环设计
BM25+向量混合检索 jieba 分词精确匹配 + FAISS 语义理解，α 参数可调
多查询扩展 LLM 生成 3 个查询变体，提升 RAG 召回率
页码溯源 每个 chunk 携带文档名+页码，回答可追溯
CASE1 舆情集成 跨项目数据联动，研报可引用最新市场情绪
Embedding 双后端 本地 bge-small-zh + DashScope API 可切换
Agent 自主迭代搜索 不是一次搜完，而是发现线索后追加搜索
增量索引 新文件自动检测，已处理文件跳过
