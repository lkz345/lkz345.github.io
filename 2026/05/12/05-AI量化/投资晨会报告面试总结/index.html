CASE5 投资晨会报告生成（多因子选股 + 板块轮动）

一句话定位

这是一个量化分析驱动的投资晨会自动化系统，包含板块数据准备、板块轮动分析、多因子选股、工作流编排四个子模块，每日定时运行后自动输出 Top 强势板块 + Top 选中标的，推送到钉钉/企业微信群。与 CASE1 的舆情分析形成”量化 + 消息面”双轮驱动。

整体架构

设计原则：CASE-D 采用”复制式独立”——把 CASE-B/C 的核心逻辑拷贝到 lib/ 目录，整个晨会 CASE 自包含可移植，不依赖兄弟目录。

CASE-A：板块数据准备（数据基础设施）

三张核心表

表名 更新频率 更新逻辑
trade_stock_status 极低频（年/季度） 从 xtdata 拉取申万一/二级分类，UPSERT 写入
trade_stock_daily 每日 08:30 按每股 MAX(trade_date)+1 增量下载 K 线，ON DUPLICATE KEY UPDATE
trade_sector_daily 每日 08:30 依赖上一步完成后，重算最近 60 日板块指数

执行顺序：① → ② → ③ 严格依赖链。CASE0 的行情采集也写 trade_stock_daily，两者互不冲突。

板块指数合成算法：等权累乘法

为什么用累乘而非简单均价：

  1. 对停牌/退市鲁棒——前一日 close_idx 已吸收，不会因成员减少出现跳空
  2. 业内主流做法（中证/申万官方都用类似累乘思路）
  3. 增量更新友好——只需当日”成份股均收益”

合成 OHLC 四维指数：用成份股的 open/high/low/close 分别对前日 close 算收益率均值，再累乘到前日 close_idx，形成完整的 K 线指数。

增量重算策略：每日重算最近 60 个交易日，修正因数据延迟（如停牌复牌补数据）导致的指数链误差。

输出字段：change_pct（等权涨幅）、涨跌家数、涨跌停家数（阈值 ±9.7%）、领涨股、合成 OHLC 指数、总量。

申万分类兼容性

  • 排除 SW2014 旧版已拆分板块（如”SW1银行”、”饮料制造”）
  • 兼容两种命名：SW2白酒 前缀 vs 白酒II 后缀
  • 带”加权”后缀的副本一律排除

CASE-B：板块轮动分析（核心量化引擎）

静态强度排名（三指标 Z-score 等权）

指标 计算 含义
MOM_21 过去 21 日板块指数累计收益率 短期资金流向
RS_60 板块 60 日收益 - 市场基准 60 日收益 中期跑赢市场的程度
VOL_RATIO 近 5 日成交额 / 近 60 日成交额 量价配合度（有量才是真涨）

综合分 = 三指标各 Z-score 后等权求和 → 横截面排名。

拐点检测（一阶导 + 二阶导 → 四象限投票）

象限 速度 v 加速度 a 描述 操作建议
accel_up v > 0 a > 0 加速上涨 / 主升浪 追涨/持有
decel_up v > 0 a < 0 减速上涨 / 顶背离前兆 减仓/观望
accel_down v < 0 a < 0 加速下跌 / 杀跌段 清仓/不接刀
decel_down v < 0 a > 0 减速下跌 / 底背离前兆 小仓试探/等右侧

投票机制（减少噪音）：

  • 速度组：ROC_20（2 票）+ MA20_SLOPE（1 票）→ 多数决
  • 加速度组：MA20_ACCEL（1 票）+ MACD_HIST 变化方向（1 票）→ 多数决

四类深度洞察（rotation_insights.py）

  1. 切换矩阵（5×5）：from_phase → to_phase 的事件数、平均超额收益、胜率
  2. 衰减曲线：5d/10d/20d 三个窗口的超额收益变化，判断信号持续性
  3. 板块信号可靠度：各板块历史”加速上涨”切换的胜率和平均超额收益排行
  4. 月度切换密度：市场温度计——牛市 accel_up 多，熊市 accel_down 多

综合视图（run_today.py）

composite_score = 强度 Z-score + phase_bonus，phase_bonus：accel_up +3.0、decel_down +2.0、decel_up +0.5、accel_down -2.0。

CASE-C：多因子选股（选股引擎）

10 因子覆盖 5 大类

类别 因子 说明
动量（3） MOM_1M / MOM_3M / MOM_6M 21/63/126 日累计收益率
反转（1） REV_5D 5 日收益取负号（短期超涨易回调）
波动率（2） VOL_20 / VOL_60 年化波动率取负号（低波好）
流动性（2） LIQ_20 / TURN_20 日均成交额对数/换手率取负号
技术指标（2） RSI_14 / BIAS_20 RSI 偏离 50 取信号 / 乖离率取负号

为什么主做技术面因子：xtdata 财务接口较弱且数据不稳定，技术面从 K 线直接算，数据可靠 + 全市场可计算。设计方向是”越大越好”，有 take_negative 参数自动取负。

预处理三件套（顺序严格）

  1. 去极值（MAD 法）：截断到 median ± 3 × 1.4826 × MAD，MAD 比 3σ 更稳健
  2. Z-score 标准化：(x - mean) / std，拉到 mean=0 / std=1 同一量纲
  3. 行业中性化：在每个申万一级行业内单独 Z-score，排除行业 beta 伪装（如银行 PE 普遍低，选低 PE 变成”全选银行”）

三种合成方式

方式 原理 优劣
等权 alpha = mean(因子) 最简单基线
IC 加权 权重 = 历史 IC 均值 / Σ|IC| 自动给有效因子加分，推荐方案
Lasso 回归 X=因子, y=未来收益 自动剔除无效因子，但过拟合风险高

分层回测验证（layered_backtest.py）

  • 每个调仓日把股票按 alpha 分 5 层，等权持有到下期
  • 单调性检验：第 5 层收益 > 第 4 层 > … > 第 1 层 → 因子有效
  • IC/IR 指标：IC 均值、IR = IC/σ(IC)，IR > 0.5 算优秀
  • Walk-forward IC 加权：用前 ic_lookback（默认 6 期）的 IC 均值作为权重，严格不用未来数据
  • Top-N 集中度回测：按 alpha 取前 5/10/20 只等权持有，对比累计收益
  • 基准对照：可拉沪深 300 指数算超额收益和最大回撤

选股池（stock_pool.py）

  • 从 xtdata 拉沪深 300 成分股（标准做法：避免全市场噪音）
  • 过滤 ST、退市、上市不足 250 天的新股
  • 反向构建 stock → 申万一级行业 映射（遍历 SW1 板块反查成分股）

CASE-D：投资晨会工作流（LangGraph 编排）

4 节点线性 DAG

节点 职责 核心逻辑
industry_node Top 板块强度排名 rank_industries_with_phase()：强度 + 拐点 → composite_score
stock_picker_node 多因子选股 从 Top 板块反查成分股 → 算因子矩阵 → 预处理 → 等权合成 → Top N
report_node 拼装晨报 Markdown + HTML 双版本，自动落盘到 outputs/reports/
push_node 推送 钉钉 + 企业微信 + 控制台三渠道

State（MorningState TypedDict）

  • 输入：trigger_time、industry_level、top_n_industries、top_n_stocks、lookback_days、sample_stocks
  • 中间产出：industry_rank、stock_pool、factor_rank、picked_stocks
  • 输出：report_md、report_html、push_result
  • 审计日志：messages（Annotated[list, add] 自动追加）

调度器（scheduler.py）

  • 用 APScheduler 的 BlockingScheduler + CronTrigger
  • 双 Job 设计：
    • 08:30（周一到周五）job_data_refresh → subprocess 调 CASE-A run_daily.py 增量更新
    • 09:00（周一到周五）job_pre_market → import build_graph() 执行工作流（比 subprocess 快）
  • 支持 --simulate 模拟模式，立刻把两个 job 各跑一次验证流程

推送兜底（pusher.py）

钉钉 → 企业微信 → 控制台，哪个 webhook 配了就走哪个，没配的跳过但不报错，控制台永远可用。

技术亮点总结

  1. 等权累乘指数合成：业内主流做法，对停牌/退市鲁棒，增量更新友好
  2. 四象限投票机制：速度 + 加速度联合判定，用多数决减少单指标噪音
  3. 预处理三件套 + 行业中性化：MAD 去极值比 3σ 更稳健，中性化排除行业 beta
  4. Walk-forward IC 加权：用历史 IC 滚动均值做权重，严格无前瞻偏差
  5. 复制式独立部署：CASE-D 自包含可移植，不依赖兄弟 CASE 目录
  6. 综合评分：composite_score = 静态强度 + 动态拐点bonus，量化 + 择时一体化
  7. 三层推送兜底：钉钉/企微/控制台，适应不同部署环境
  8. 双入口设计：run_init.py 全量初始化 + run_daily.py 每日增量，依赖链清晰
