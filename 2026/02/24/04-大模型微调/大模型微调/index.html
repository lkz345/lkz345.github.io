二、什么是LoRA（Low-Rank Adaptation）低秩适配器

LoRA → 秩 → 矩阵 → 神经网络 → 损失函数

什么是Low-Rank，秩：一个矩阵标准形，非0行的行数。

第一行和第三行的信息量相同，秩为2。

数据的表达：Scalar → Vector → Matrix → Tensor 标量矢量矩阵张量

训练的结果是矩阵，求出大数量级的权重参数来拟合表达实际意义，直接求解是直线。

元素 含义 关键信息
蓝色大矩阵 W ∈ ℝ^(d×d) 预训练模型的权重矩阵（比如 Transformer 注意力层的W_q/W_v） 维度极高（d通常是几百～几千，比如d=4096），参数规模是 d²，全程冻结，不更新
上方橙色矩阵 B LoRA 的低秩矩阵之一，维度 d×r 初始化时 B=0，训练中更新
下方橙色矩阵 A LoRA 的低秩矩阵之二，维度 r×d 初始化用正态分布 𝒩(0,σ²)，训练中更新
中间的 r 秩（Rank），LoRA 的核心超参数 r ≪ d（比如d=4096时，r通常取 8/16/32），这就是 “低秩” 的来源

先降秩：把原本高维的更新量 ΔW，用两个低秩矩阵的乘积近似，强制限制它的秩为很小的 r

再相加：把这个低秩的更新量，和原权重 W 的计算结果（或权重本身）做加法融合，得到微调后的效果

第一步：「先降秩」—— 对更新量 (\Delta W) 做低秩分解

1. 传统微调的问题：更新量是高维的

全量微调时，我们会直接修改原权重，得到新权重 (W’ = W + \Delta W)，其中：

  • (W \in \mathbb{R}^{d \times d})（比如 Transformer 注意力层的 (W_q)，维度 d 通常是 1024/4096）
  • (\Delta W) 是和 W 同维度的更新矩阵，参数规模是 (d^2)（比如 (d=4096) 时，(\Delta W) 有 1600 万 + 参数）

但 LoRA 发现：微调时的更新量 *(\Delta W)* 本身是「低秩的」—— 大模型预训练已经学到了通用知识，微调只需要在一个很小的低维子空间里调整，不需要修改 (d^2) 这么多维度的参数。

2. LoRA 的降秩操作：把 (\Delta W) 拆成两个低秩矩阵的乘积

LoRA 用你图里的两个橙色矩阵 A 和 B，来近似这个高维的 (\Delta W)：

(\Delta W = B \times A)

  • 矩阵维度：(B \in \mathbb{R}^{d \times r})，(A \in \mathbb{R}^{r \times d})
  • 关键限制：(r \ll d)（比如 (d=4096) 时，r 通常取 8/16/32）
  • 降秩的本质：两个低秩矩阵的乘积，秩最多不超过 r，所以 (\Delta W) 的秩被强制限制在 r，实现了「降秩」
3. 降秩带来的参数压缩（和图里的 r 直接相关）

原来的 (\Delta W) 有 (d^2) 个参数，现在只需要训练 A 和 B，总参数是 (d \times r + r \times d = 2dr)。

举个你之前场景的例子：

  • 当 (d=4096)，(r=8) 时：
    • 原更新量参数：(4096^2 = 16777216)
    • LoRA 降秩后参数：(2 \times 4096 \times 8 = 65536)
    • 参数规模直接压缩了 256 倍！

第二步：「再相加」—— 把低秩更新量和原权重融合

降秩后的 (\Delta W = B \times A)，最终要和原权重 W 结合，得到微调后的效果。LoRA 有两种「相加」的方式，都和你图里的结构对应：

方式 1：在线计算相加（训练 / 推理都通用，不修改原权重）

前向传播时，原权重和 LoRA 更新量的计算结果分开算，再相加：

(\text{Output} = Wx + \Delta W x = Wx + B \times (A \times x))

对应你图里的流程：

  • 左边蓝色的 W 做 Wx 计算
  • 右边橙色的 A 和 B 做 (B \times A \times x) 计算
  • 最后把两个结果相加，就是微调后的输出

这种方式的好处是：原权重 W 全程不动，LoRA 可以随时插拔切换，不会破坏原模型的通用能力。

方式 2：离线权重融合（推理时常用，无额外开销）

推理前，把 (\Delta W = B \times A) 直接加到原权重 W 里，得到融合后的权重 (W’ = W + \Delta W)，之后就和普通模型一样直接计算 (W’x)，不会增加任何推理延迟。

核心参数 1：r = 16（LoRA 的秩，降秩的核心）

对应原理：先降秩

这就是你关心的低秩维度 r！

  • 矩阵 A 维度：d × r
  • 矩阵 B 维度：r × d
  • r 越小 → 降秩越彻底 → 参数越少 → 显存占用越低
  • r 越大 → 低秩矩阵表达能力越强 → 微调效果越好（但参数变多）

直观计算（以模型维度 d=4096 为例）

LoRA 总参数 = 2 × d × r

  • r=8：2×4096×8=65536 个参数
  • r=16：131072 个参数
  • 原模型：数十亿参数，差距上万倍

选择建议

  • 通用任务：8 / 16 足够
  • 复杂任务（代码、专业领域）：32 / 64
核心参数 2：target_modules（给哪些层加 LoRA）

对应原理：选择哪些权重矩阵 W 附加低秩更新

这些是 Transformer 大模型的核心线性层（就是我们说的高维权重 W）：

  1. 注意力层（Transformer 核心）
    • q_proj / k_proj / v_proj：查询 / 键 / 值投影层
    • o_proj：注意力输出投影层
  2. 前馈层（FFN，负责理解语义）
    • gate_proj / up_proj / down_proj

为什么选这些层？

这些层是模型语义理解、特征转换的核心，在这些层插入低秩矩阵 A/B，就能用最小的参数，让模型学会新任务。

核心参数 3：lora_alpha = 16（低秩更新缩放系数）

对应原理：再相加时的缩放权重

LoRA 的输出公式：

(\text{LoRA输出} = \Delta W = \frac{\alpha}{r} \times B \times A \times x)

变形后的 rank square root LoRA：(\text{rsLoRA输出} = \Delta W = \frac{\alpha}{\sqrt{r}} \times B \times A \times x)

  • alpha 是缩放系数，用来调整低秩更新的权重
  • 行业默认：lora_alpha = r（这里 r=16，alpha=16，缩放系数 = 1）
  • 作用：控制「LoRA 新增的知识」对原模型的影响强度
正则化与偏置项
  • lora_dropout=0：关闭 dropout，Unsloth 官方最优配置，训练更快、显存更低
  • bias="none"：不训练任何偏置参数，进一步减少参数量，最优配置
显存优化：梯度检查点
  • 作用：用时间换显存，牺牲极少量速度，节省 30%~50% 显存
  • "unsloth"：Unsloth 定制优化版，比原生 PyTorch 更高效
  • 长文本（8k/32k 上下文）必开
辅助参数
  • use_rslora：Rank-stabilized LoRA，解决小 rank 训练不稳定问题,变形后的 LoRA：(\text{rsLoRA输出} = \Delta W = \frac{\alpha}{\sqrt{r}} \times B \times A \times x)
  • loftq_config：低精度微调技术，极限省显存。 打开这个参数，会有一套算法初始化LowRank矩阵。花了一些时间，有可能让微调更快

LoRA 的完整流程（Step-by-Step）

整个 LoRA 的生命周期可以分为以下 4 个阶段：

1. 初始化阶段（准备外挂）

  • 冻结原模型（Freeze）： 将预训练大模型的所有原始参数 $W_0$ 全部锁定，训练过程中不计算它们的梯度，也不进行更新。
  • 构建旁路（Adapter）： 在原模型紧挨着的平行位置，引入 $A$ 和 $B$ 两个低秩矩阵。
  • 权重初始化： * 矩阵 $A$ 采用高斯分布随机初始化。
    • 矩阵 $B$ 采用全零（Zeros）初始化。
    • 为什么要这样？ 因为这样在训练开始的第一步，$B \times A = 0$，整个外挂的输出为 0，模型表现和原模型完全一致，保证了训练的平滑起点。

2. 前向传播阶段（Forward Pass）

当一条输入数据 $x$ 进入模型时，它会同时走两条路：

  1. 主路： 经过冻结的原模型，输出 $W_0x$。
  2. 旁路： 经过低秩矩阵，先乘 $A$ 降维，再乘 $B$ 升维，输出 $BAx$。

最终的输出 $h$ 是这两条路结果的叠加：

$$h = W_0x + \Delta Wx = W_0x + \frac{\alpha}{r}BAx$$

注： $\frac{\alpha}{r}$ 是一个缩放因子（Scaling Factor），其中 $\alpha$ 是一个常数，用来调节外挂矩阵对原模型的影响权重。

3. 反向传播与训练阶段（Backward Pass）

  • 计算损失函数（Loss）。
  • 在梯度回传时，只计算并更新矩阵 $A$ 和 $B$ 的参数。
  • 因为需要更新的参数量极少（通常不到原本的 1%），所以显存占用大幅降低，训练速度极快。

4. 推理与部署阶段（Inference / Deployment）

到了算力结算的时候，LoRA 还有一个优雅的绝活——无缝合并。

在训练完成后，我们可以直接把 $B \times A$ 的矩阵加到原本的 $W_0$ 里，融合成一个新的权重矩阵：

$$W_{new} = W_0 + BA$$

  • 合并的好处： 在实际线上推理（Inference）时，不需要任何额外的计算延迟和显存占用。
  • 热插拔优势： 如果你有多个任务（如客服、代码、翻译），你只需要保存几兆大小的 LoRA 权重文件。针对不同用户，随时在内存里“插拔”组合不同的 $BA$ 矩阵即可。

一轮完整训练闭环（前向 + 反向 串联 LoRA 全流程）

结合你之前整理的 LoRA 四阶段，串起完整训练步骤：

  1. 初始化：冻结 (W_0)，初始化 (A、B)（B 全 0）
  2. 前向传播：输入 x → 主路 + 旁路计算 → 输出 (h = W_0x + \frac{\alpha}{r}BAx)
  3. 计算损失：对比预测结果和真实标签，算出 Loss
  4. 反向传播：误差反向回传 → 只计算 (A、B) 的梯度，(W_0) 梯度被截断
  5. 参数更新：优化器用梯度微调 (A、B)
  6. 循环：重复 2~5 步，直到 Loss 收敛、模型训练完成

训练结束后进入推理：可选择把 BA 融合进 (W_0)，之后只跑纯前向传播。

对比维度 前向传播 Forward 反向传播 Backward
数据流向 输入 → 输出（正向） 输出误差 → 输入（反向）
核心目标 计算模型预测结果 计算误差梯度、更新参数
参数变化 参数只读、不修改 根据梯度修改权重参数
梯度计算 不计算梯度 逐层计算梯度（核心动作）
算力特点 计算矩阵运算为主 链式求导为主
使用场景 训练 + 推理 / 部署 仅训练阶段（推理不用）
LoRA 特殊行为 主路 + 旁路并行计算，先降秩再相加 梯度截断，仅更新 、，不碰 W0

AdaLoRA

AdaLoRA（Adaptive Low-Rank Adaptation，自适应低秩适应） 是 LoRA 技术的一个重要进阶版本（发表于 ICLR 2023）。

如果说经典 LoRA 是“大锅饭”（给模型的所有层都分配相同大小的秩 $r$），那么 AdaLoRA 就是“精准扶贫”（动态调整算力预算，把更多的参数量分配给重要的层，把不重要的层裁剪掉）。

以下是 AdaLoRA 的核心原理和工作机制的详细拆解：

核心痛点：经典 LoRA 的不合理之处

在经典的 LoRA 中，用户必须为模型的所有线性层（如 Attention 的 $Q, K, V$ 矩阵和 FFN 层）设定一个固定的秩 $r$（比如全是 $r=8$）。

然而，大模型不同层、不同模块的作用是完全不同的：

  • 有些关键层负责处理复杂的逻辑，需要更强的表达能力（需要更高的 $r$）。
  • 有些层只负责传递基础特征，信息量很低（较低的 $r$ 甚至 $r=0$ 就够了）。

如果一刀切地给所有层分配相同的 $r$，就会导致“有些层吃不饱（欠拟合），有些层吃不下（浪费显存和参数量）”。

AdaLoRA 是如何工作的？

AdaLoRA 改变了传统 LoRA 的矩阵拆分方式，并引入了动态裁剪机制。它的核心流程可以分为以下三个步骤：

1. 改变游戏规则：引入类 SVD（奇异值分解）形式

传统的 LoRA 将权重变化表示为 $\Delta W = B \times A$。

而 AdaLoRA 将其改写为类似 SVD（奇异值分解） 的形式：

$$\Delta W = P \times \Lambda \times Q$$

  • $P$ 和 $Q$：两个低秩矩阵（类似于 SVD 中的左、右奇异向量）。
  • $\Lambda$（Lambda）：一个对角矩阵（Diagonal Matrix），对角线上的每一个元素（奇异值）直接对应了某一个特定“秩维度”的权重大小。

为什么要这样做？ > 这样设计极其聪明。如果我们要降低某一个层的秩，不需要复杂的矩阵重构，只需要把 $\Lambda$ 矩阵中对应位置的元素（以及 $P$ 和 $Q$ 对应的行列）直接删掉（变成0）就可以了。

类似图像的谱分解，只保留主要特征，剔除影响小的特征。

2. 智能评估：计算“贡献度”（Importance Metric）

在训练过程中，AdaLoRA 会实时监控每一组三元组（$P$ 的一列、$\Lambda$ 的一个对角元素、$Q$ 的一行）对模型最终表现的贡献。

它评估重要性的依据不仅看参数的绝对值大小（Magnitude），还会看梯度的大小（Gradient）。如果一个参数的值很大，或者它的梯度变化很剧烈，说明它在当前任务中非常关键。

3. 动态预算分配：定期“优胜劣汰”

AdaLoRA 会在训练过程中设置一个总参数预算（Total Budget）。

  • 在训练初期，先给所有层一个相对较高的初始秩。
  • 每隔一定的训练步数（Steps），算法就会对全网所有的奇异值进行重要性排名。
  • 无情裁剪：排名靠后的、对模型贡献微乎其微的三元组会被直接清零并冻结。
  • 保留精英：重要的模块则继续保留较高的秩。

通过这种“优胜劣汰”的动态调整，最终模型会自发地把参数集中在真正需要微调的关键位置。

AdaLoRA 的优势

  • 用最少的参数，办最漂亮的事： 实验表明，在相同参数量限制下，AdaLoRA 的模型表现通常优于经典 LoRA。
  • 省去调参痛苦： 你不再需要纠结到底该给大模型的哪一层单独设置多少的 $r$，AdaLoRA 会在训练过程中自动帮你“摸索”出最佳的分配方案。
  • 推理同样零成本： 尽管训练过程变得智能化了，但最终在部署时，$\Delta W = P\Lambda Q$ 依然可以完美地合并（Merge）进原始模型的权重中，不带来任何额外的推理延迟。

LongLoRA

LongLoRA（Long Low-Rank Adaptation） 是由香港中文大学和贾佳亚团队（于 2023 年）提出的一种专门用来极其高效地扩展大模型上下文长度（Context Length）的微调技术。

如果说经典 LoRA 解决了“显存不够，怎么微调大模型”的问题，那么 LongLoRA 解决的就是“显存和算力极其有限，怎么把模型的理解长度从 4k 猛增到 100k”的问题。

核心痛点：长文本微调的两大“大山”

想让一个原本只能读 4096 个 Token 的模型（比如基础版 LLaMA 2）去读 10 万字的长文，传统方法有两大计算瓶颈：

  1. 注意力机制（Attention）的计算量爆炸： 标准自注意力机制的计算复杂度和显存占用是平方级别 $O(N^2)$ 的。上下文扩大 4 倍，计算量和显存直接飙升 16 倍！
  2. 单纯 LoRA 效果差： 实验发现，如果直接用经典的 LoRA 去做长文本位置插值（Position Interpolation）微调，模型效果会非常糟糕，无法很好地适应超长文本。

LongLoRA 通过两个极其精妙的改进，把这两座大山全部搬走了。

LongLoRA 是如何工作的？（核心两大支柱）

LongLoRA 的核心创新可以总结为：训练时用“局部注意力”偷懒，微调时把“关键层”放开。

1. 平行移动的短注意力（Shifted Short Attention, $S^2$-Attn）

为了干掉 $O(N^2)$ 的注意力计算暴涨，LongLoRA 在训练阶段引入了 $S^2$-Attn 机制：

  • 分组（Group）： 它把原本超长的文本（比如 8192 个 Token）切分成几个小格子（比如 4 个格子，每个 2048 Token）。在每个格子里独立计算注意力。这样计算量就从 $8192^2$ 降到了 $4 \times 2048^2$，直接省了大钱。
  • 平移（Shift）： 如果只在格子里计算，格子之间不就“老死不相往来”了吗？长文本的连贯性就断了。LongLoRA 的天才之处在于：它把一半的注意力头（Attention Heads）往后平移了半个格子的长度。

生动比喻： > 就像手拉手排队，如果大家都只和身边固定的小组说话，信息就传不开。但如果第二排的人集体向右对齐移动半个位置，原本分属两个小组边界的人就能说上话了。

这种设计只用在训练时，只需要两行代码就能实现，却完美模拟了全局注意力的信息流动！而在推理（Inference）阶段，模型依然可以无缝切换回完整的全局自注意力。

2. 解冻嵌入层与归一化层（Trainable Embedding & Normalization）

论文作者在研究中发现了一个被大部分人忽略的秘密：在扩展长文本时，光靠微调 Attention 层的参数（经典 LoRA 的做法）是不够的。

长文本微调高度依赖于模型对位置编码（Position Embeddings）和特征增量的微调。因此，LongLoRA 在使用 LoRA 的同时，特意解冻（放开训练）了两个关键部分：

  • Embedding 层（嵌入层）
  • Normalization 层（如 RMSNorm / LayerNorm 归一化层）

虽然多训练了这两个部分，但它们的参数量极小，却成了长文本扩展成功的关键药引。

LongLoRA 的逆天战绩与优势

  • 平民设备挑战极限： 在标准的 8 张 A100 显卡上，全量微调（Full Fine-tuning）最多只能把 LLaMA 2 7B 扩展到 16k 窗口。而使用 LongLoRA，同样长文本下能节省数十倍算力，甚至在一台机器上就能把模型疯狂扩展到 100k 上下文！
  • 推理完全兼容： 因为它没有破坏大模型的底层架构，训练完后，LoRA 依然可以融合进原模型。推理时，你可以直接搭配 FlashAttention-2 等加速技术使用。
  • 完美保留短文本能力： 很多长文本微调方法会导致模型变笨（在短文本任务上表现下降），而 LongLoRA 在极具扩展长文本能力的同时，短文本的困惑度（Perplexity）几乎没有劣化。

Prompt Tuning（提示词微调）：

发生在输入层。它像是在文章开头加了几个“神秘的隐藏单词”（软提示向量），试图通过改变输入来引导模型的输出

让机器帮你去寻找合适的提示词

prompt tuning 完整流程:

  1. 准备阶段： 预留几个虚拟提示词位置（Soft Prompt），并完全锁定大模型的参数。
  2. 训练阶段： 将虚拟提示词的 Embedding 和输入问题的 Embedding 拼接，喂给大模型得到输出。计算损失（Loss），通过梯度下降只更新虚拟提示词的向量参数。重复多次，直到这组向量完美。
  3. 保存阶段： 把这组训练好的、针对特定任务的提示词向量（通常只有几十 KB）保存下来，命名为“任务 A 的专属皮肤”。
  4. 使用阶段（推理）： 当有关于任务 A 的新问题进来时，直接把“任务 A 的专属皮肤”向量拼在问题前面，一起喂给大模型，大模型就能直接输出完美答案。

判断任务类别

（也就是决定给大模型挂载哪一个“专属插头”）通常有以下三种主流的设计方案：

1. 业务端天然隔离（最常见、最稳妥）

在绝大多数真实的商业应用中，任务类别在用户点击具体功能的那一刻就已经确定了。

  • 例子： 用户在电商后台点击了“一键生成商品文案”的按钮，或者在翻译软件里选择了“中译英”模式。
  • 逻辑： 后端的代码（如 Python/Java Web 框架）收到请求时，就已经知道对应的 API 路由是 /api/generate_copy 还是 /api/translate。系统会根据路由，自动在后台把对应的 copy_prompt.bin 或 translate_prompt.bin 拼接上去。这种情况下，根本不需要算法去猜用户的意图。

2. 前置“意图路由网关”（Intent Router）

如果你的界面像 ChatGPT 一样，只有一个空荡荡的输入框，用户丢进来什么完全不可控，这就需要用到网关分类。

在复杂的全能型 AI 架构中，通常会采用“小模型带大模型”的组合拳：

  • 怎么做： 在昂贵的大模型前面，挡一个体量极小、速度极快的“前置分类器”（比如一个轻量级的 BERT、一个几百 MB 的文本分类小模型，甚至是基于向量检索的语义路由器 Semantic Router）。
  • 具体流程：
    1. 用户输入：“帮我把这句话翻译成法语：你好。”
    2. 前置小模型耗时 2~5 毫秒迅速做出判断：这是一个“翻译”任务。
    3. 系统根据这个判断，自动调出“翻译专属插头”（Soft Prompt 向量），和用户输入拼在一起。
    4. 最终送给后面的千亿级大模型进行高质量输出。
  • 优势： 小模型判断意图成本极低、速度极快，用它来当“分诊台导医”，可以完美解决单入口的路由问题。

3. 用户显式指定（关键字 / 斜杠命令）

类似于 Notion AI、Discord 或者目前很多生产力工具的做法。

  • 例子： 用户在输入框中输入 /summary 请帮我总结这段话... 或者 /code 写个冒泡排序。
  • 逻辑： 系统通过前端或简单的正则匹配直接解析 / 后面的关键字，精准匹配并加载对应的任务软提示向量。

flatten：

把卷积层输出的「多维特征图」，强行拉伸成「一维长向量」，不改变数据本身，只改变数据的形状。

与tokenize相同点（共通之处）

  1. 都是预处理步骤：为下游模型 / 计算做准备，不直接参与核心计算；
  2. 都做数据格式转换：把原始数据转为更适配输入的格式；
  3. 最终输出常为一维序列：这是两者最易混淆的地方；
  4. 通用深度学习工具：广泛用于大模型、神经网络 pipeline。

不同之处

对比维度 flatten（展平） tokenize（分词）
核心目标 统一数据维度，适配模型输入 文本转语义单元，让模型读懂文本
操作对象 多维张量、嵌套列表 / 数组 连续自然语言文本
数据内容 完全不变（仅挪动位置） 被切分（生成新 token）
数据结构 强制降维（多维→一维） 无维度要求（文本→token 序列）
输出含义 纯原始数据的结构重组 有语义的最小语言单元
专属场景 神经网络、数据结构处理 NLP、大模型文本预处理

总结

  • flatten 是「结构工」：只整理数据形状，不碰内容；
  • tokenize 是「语义工」：只切分文本内容，生成语义单元；
  • 两者无替代关系，是预处理中各司其职的两个步骤。

Style GAN

StyleGAN1【Karras etal.22019】架构。这一新颖的架构基于渐进式生长方法(b，右侧)，并结合了风格注入机制(b，中间)。此外，一个映射网络(b，左侧)负责对高斯Z空间进行变形，以更好地匹配训练数据的分布。

Style GAN = 可控高质量图像生成之王：用映射网络 + 风格向量 + 分层控制，把 “随机瞎生成” 变成 “精准调参数”，从人脸到万物，从 2018 年一直统治高质量图像生成至今。

Cycle GAN

CycleGAN 加了一条强约束：

  • 前向循环：x → G(x) → F(G(x)) ≈ x（马 → 斑马 → 变回马）
  • 后向循环：y → F(y) → G(F(y)) ≈ y（斑马 → 马 → 变回斑马）

作用：保证内容不变、只换风格 / 属性。

CycleGAN：跨域转换、无配对、内容不变换风格（马→斑马）

StyleGAN：单域生成、可控属性、从潜空间造新图（生成人脸、调年龄 / 发型）

商业公司更愿意使用vLLM，高并发响应比Ollama快多倍。做了很多优化：

Tensor

分块管理：将每个请求的 KV Cache 按固定大小切分为逻辑块（Block），每个块存储固定数量 token 的 K/V 向量；逻辑上连续的序列，在物理显存中可以存储在不连续的物理块里。

块表映射：通过「Block Table（块表）」维护逻辑块到物理块的映射关系（如图中逻辑块 0 映射到物理块 7，逻辑块 1 映射到物理块 1），推理时通过块表寻址即可，无需物理内存连续。

解决的传统痛点：

  • 传统 KV Cache 需要为每个请求预分配连续显存，短序列会产生大量内部空间浪费；
  • 请求频繁创建销毁会产生外部显存碎片，空闲显存无法被有效复用

对于拥有相同前缀的多个请求（比如相同的系统提示词、相同的上下文输入），vLLM 可以让多个请求的块表指向同一份物理 KV 块，同一份前缀 KV Cache 全局仅存储一份。

  • 典型场景：批量问答、多轮对话共享系统提示、RAG 场景共享检索上下文，能大幅减少重复 KV 数据的显存占用，并发量越高显存节省越明显。

3-4-1 BLEU

  • 核心思想：**围绕准确。**模型回答里的词，跟标准答案里的词，逐词比对，看重复了多少。
  • 打个比方：标准答案是“长江和黄河”。模型说“长江”——词对上了1个，但漏了“黄河”，分数中等。模型说“黄河长江”——词全对，顺序不同，BLEU会扣分（因为它对词序敏感）。
  • 适合场景：翻译、摘要——要求用词精确，不能乱加词。

3-4-2 ROUGE

  • 核心思想：围绕召回。标准答案里的重要信息，模型有没有覆盖到。
  • 打个比方：标准答案是“长江和黄河”。模型说“中国最长的两条江：长江（6300公里）和黄河（5464公里）”——虽然多了很多字，但“长江”“黄河”两个关键信息都覆盖了，ROUGE分数很高。模型说“黑龙江和松花江”——信息全错，ROUGE为0。
  • 适合场景：问答、摘要——允许模型换种说法，但关键点不能丢。

LlamaIndex介绍 一句话解释 LlamaIndex 是一个用于构建 LLM 知识库问答（RAG）系统的框架，它让你可以把文档、数据库、网页等数据接入大模型，实现智能问答。 LlamaIndex和LangChainLlamaIndex的核心目标是数据检索增强（RAG），专注于从大量的非结构化数据（如文档、网页等）中提取信息并提供自然语言查询的能力，帮助开发者轻松地将大型数据集转化为可以用自然语言查询的知识库，让LLM更好地理解你的数据和快速找到你要的数据。（LlamaIndex更适合构建企业级知识库） LangChain的核心目标chain和工作流（Agent），设计用于构建基于语言模型的应用程序。它不仅限于处理文本数据或提供查询功能，还支持创建复杂的对话代理（Chatbots）、自动化任务执行（Agents）、以及与其他服务集成等，让LLM更好地执行复杂任务。（LangChain更适合多工具协作的Agent） 功能对比： 功能 LlamaIndex LangChain 文档加载 ✅ 强（支持多格式、结构化数据） ⚠️ 基础功能，依赖其他库 向量索引 ...
